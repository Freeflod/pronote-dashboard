# Suivi des issues

Le suivi se fait dans les issues GitHub de ce dépôt.

- Un bug ou une idée hors du périmètre d'une PR en cours devient une issue, pas seulement un commentaire dans le code. Une dette acceptée crée une issue (étiquette `dette`).
- **Aucune donnée réelle dans une issue** : ni nom d'élève, de parent ou d'établissement, ni note, ni devoir, ni jeton, ni URL de serveur Pronote, ni capture d'un vrai compte. Décrire avec des comptes (« 3 évaluations ») ou des données inventées.
- Un bug décrit : version du plugin, version d'Obsidian, mobile ou ordinateur, mode (Enfant ou Parent), étapes, résultat attendu, résultat obtenu.
- Une PR qui corrige une issue écrit `Closes #N` dans sa description.
- Une décision de conception née d'une issue s'écrit en ADR (`docs/adr/POLICY.md`).
- Les failles de sécurité ne s'ouvrent pas en issue publique : voir `docs/SECURITY.md`.
